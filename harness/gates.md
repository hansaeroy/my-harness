# Codex 하네스 게이트 기준

## G1. 레퍼런스 분석 게이트

통과 조건:

- 서로 다른 사이트 레퍼런스가 5개 이상이다. [D10: 제안 기본값, 문서 근거 없음]
- 각 레퍼런스의 URL, 레이아웃 구조, 분위기, 서비스 반영 후보가 모두 비어 있지 않다. [D11: 레이아웃·분위기·반영 후보는 사용자 작업 2단계, URL과 비어 있지 않은 조건은 제안 기본값]

실패하면 레퍼런스 검색·분석 단계로 돌아간다. [D06]

## G2. 화면 설계·컨셉 확정 게이트

기계 통과 조건:

- 키스크린 수가 2~3개다. [D12: 사용자 작업 4단계]
- 각 키스크린 프레임 크기가 390×844다. [D12: 사용자 작업 4단계, `docs/design.md` 모바일 기준]
- MVP 제외 항목인 마켓 노출, 구매, 결제, 정산, 판매 중·판매 중지 상태가 0개다. [D13: `docs/PRD.md` 6-6 및 MVP 1차 범위 결정]
- 판매 신청 허용 역할은 `seller`만이다. [D13: `docs/PRD.md` 7-4]
- 판매 신청의 최종 검수 상태는 `approved`다. [D13: `docs/PRD.md` MVP 1차 범위 결정]

유일한 사람 승인 지점:

- 내부 관계자가 컨셉을 확정한다. [D14: 사용자 작업 5단계]
- 승인 전에는 디자인 제작 단계로 넘어가지 않는다. [D14: R5 승인]

실패하면 화면 설계 단계로 돌아간다. [D06]

## G3. 디자인 검토 게이트

통과 조건:

- `docs/design.md` 기준 색상 위반이 0건이다. [D15: 범주는 문서 근거, 0건은 사용자 승인]
- `docs/design.md` 기준 타이포그래피 위반이 0건이다. [D15]
- `docs/design.md` 기준 간격 위반이 0건이다. [D15]
- `docs/design.md` 기준 모서리 위반이 0건이다. [D15]
- `docs/design.md` 기준 컴포넌트 위반이 0건이다. [D15]

실패하면 디자인 제작 단계에서 수정한 뒤 다시 검토한다. [D06]
