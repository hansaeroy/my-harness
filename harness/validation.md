# Codex 하네스 검증과 리뷰

## 정상 통과 시나리오

- G1~G3가 모두 통과하는 입력으로 전체 파이프라인을 실행한다. [D19]
- 산출물, 게이트 판정, 사람 승인 위치가 설계된 순서와 일치하는지 확인한다. [D19]

## 게이트 실패 시나리오

- G1: 레퍼런스 수가 기준 미만이거나 필수 분석 필드가 비어 있는 입력을 사용한다. [D10, D11, D19]
- G2: 키스크린 수 또는 크기가 잘못된 입력을 사용한다. [D12, D19]
- G2: MVP 제외 기능이나 판매 중·판매 중지 상태가 있거나, 판매 신청 역할이 `seller` 외에 포함되거나 최종 검수 상태가 `approved`가 아닌 입력을 사용한다. [D13, D19]
- G3: 색상, 타이포그래피, 간격, 모서리, 컴포넌트 기준을 각각 위반한 입력을 사용한다. [D15, D19]
- 각 실패에서 정확한 실패 조건이 보고되고 다음 단계로 진행하지 않는지 확인한다. [D19]

## 재개 시나리오

- G1 실패는 레퍼런스 검색·분석 단계로 돌아간다. [D06]
- G2 실패는 화면 설계 단계로 돌아간다. [D06]
- G3 실패는 디자인 제작 단계로 돌아간다. [D06]
- 유효한 완료 산출물이 있는 단계는 건너뛰고 복귀 단계부터 실행하는지 확인한다. [D09, D19]
- 재개 시 화면 설계 파일이나 승인 Figma snapshot 해시가 바뀌면 이전 G2 승인이 실패하는지 확인한다. [D24]
- 저장된 Figma snapshot만 제출하면 G2/G3가 통과하지 않고, 판정자의 라이브 MCP metadata가 있어야 통과하는지 확인한다. [D25, D29]
- 부정 문장 안에 금지 기능 단어가 있어도 무관한 prose는 통과하고, `features[].id`에 금지 기능 ID가 들어가면 실패하는지 확인한다. [D26]
- 역할 guard가 소유 폴더 밖 편집과 judge 편집을 차단하는지 확인한다. [D27]
- 이전 `docs/harness-*.md` 경로가 AGENTS, 역할 지침, 파이프라인 입력 목록에 남지 않는지 확인한다. [D26]

## 판정과 증거

- 읽기 전용 판정자가 산출물과 `harness/rules.json`을 기준으로 평가한다. [D17]
- 판정자는 파일을 수정하지 않는다. [D17]
- `runs/{run_id}/validation-report.md`에 실행 결과, 게이트별 `PASS`/`FAIL`, 실패 조건, 복귀 단계를 기록한다. [D19]

## 재실행 명령

- 규칙·출처 ID·stale path 검사: `npm run check`
- gate 재현 테스트: `npm test`
- Git pre-commit 설치: `npm run install:git-hooks` (이 폴더가 Git 저장소일 때)
- Codex 프로젝트 hook은 hook 신뢰 화면에서 정의를 검토하고 신뢰해야 실행된다. [D27]
