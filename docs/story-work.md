# 실제 작업 흐름: 홈페이지 레퍼런스 기반 화면 설계

출처: 사용자가 R1-B 인터뷰에서 설명한 실제 수작업 경험.

## 실제 작업 문장

| # | 작업 흐름 |
|---|---|
| 1 | 나는 UIBowl에서 경쟁사 레퍼런스를 수집한다. |
| 2 | 나는 레퍼런스를 분석하고 우리 서비스에 반영할 요소를 가져온다. |
| 3 | 나는 분석 내용을 토대로 서비스 화면 설계 문서를 구체화한다. |
| 4 | 나는 Figma에서 레퍼런스와 화면 설계서를 반영한 UI 키스크린 2~3개를 390×844 크기로 그린다. |
| 5 | 나는 내부 관계자들과 협의해 컨셉 시안을 확정한다. |
| 6 | 나는 확정된 시안을 바탕으로 디자인 토큰과 컴포넌트를 만들고 화면 디자인을 진행한다. |
| 7 | 나는 완성된 시안이 우리 가이드의 토큰·컴포넌트 기준을 위반하는지 검토한다. |

## 명사와 산출물

- 경쟁사 레퍼런스
- 레퍼런스 분석 내용
- 서비스 반영 요소
- 화면 설계 문서
- Figma UI 키스크린 2~3개 (390×844)
- 컨셉 시안
- 디자인 토큰
- 컴포넌트
- 완성 시안
- 가이드 위반 검토 결과

## 멈칫과 게이트

- 5단계: 내부 협의 후 컨셉 시안 확정
- 7단계: 완성 시안의 가이드 준수 검토

## 사람·도구 경계

- 4단계: Figma 사용
- 5단계: 내부 관계자와 협의
- 5단계에서 결과물을 명시적으로 넘기는지는 확인되지 않음
